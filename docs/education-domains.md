# Education eligibility

Reviewed 2026-10-16. Eligibility is derived on the server, only after email
verification. A host must end in a dot plus one of the namespaces below; merely
containing `edu` is not enough. Subdomains of institutions are supported.

| Namespace | Registry / authority evidence |
| --- | --- |
| `.edu` | [EDUCAUSE eligibility](https://net.educause.edu/faq/eligibility) |
| `.edu.tw` | [TWNIC report: delegated to the Ministry of Education](https://service.twnic.tw/file/nt/124.pdf) |
| `.edu.au` | [Education registrar eligibility](https://domainname.edu.au/eligibility.htm) |
| `.edu.hk` | [HKIRC eligibility and required documents](https://www.hkirc.hk/en/our-services-support/domain-services/eligibility-required-documents/) |
| `.edu.sg` | [SGNIC namespace rules](https://www.sgnic.sg/ExtFiles/eGuide/part2-3.html) |
| `.edu.my` | [MYNIC eligibility FAQ](https://www.mynic.my/resources/domains/faq) |
| `.edu.vn` | [VNNIC domain system](https://vnnic.vn/en/dns) |
| `.edu.cn` | [CERNIC registration authority](https://www.nic.edu.cn/home.html) |
| `.edu.ph` | [PHNET government-recognized school requirements](https://services.ph.net/dns/requirements.html) |
| `.edu.tr` | [TRABIS documented allocation rules](https://www.trabis.gov.tr/content/Belgeli) |

Not every country has an `edu.<cc>` educational namespace. In particular do not
infer `.edu.us` or `.edu.id` from their spelling. Indonesia's current registry
rules specify `.ac.id` and `.sch.id`; these are outside this initial `edu` policy.
Add other countries after checking their registry's current allocation rules.
This is a namespace eligibility policy, not proof of an individual's student
status; institution staff and alumni mailboxes can also qualify.

Education permanently includes Plus-equivalent storage, note count, encryption,
organization, Agent allowance and AstraPass count. Existing paid balances are
consumed first; then Education applies. Accounts with matching educational email
addresses cannot create new paid orders, even while that email is unverified.
Already-created invoices and existing balances remain usable.
Admin and Beta retain their higher privileges. Mail verification, not a client
flag or an unverified address, controls eligibility.
